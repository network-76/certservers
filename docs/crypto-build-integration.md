# 铜锁构建集成方案（实施前约束）

- 状态：实施方案，尚未接入实际密码 API。
- 主测版本：Tongsuo 8.5.0；对照版本：8.4.0（若执行时出现更新的 8.4.x 正式补丁，按验证计划更新）。
- 当前阶段：先建立可明确选择、可审计的依赖发现与验证方式；不把系统 OpenSSL 自动当作铜锁，也不将其误链接进生产二进制。

## 1. 依赖来源原则

1. 铜锁由独立前缀安装（例如实验环境的 `/opt/tongsuo-8.5.0`），源码版本和构建参数必须记录。
2. 构建时通过显式的 `TONGSUO_ROOT` 指定头文件与库搜索范围；不依赖全局覆盖系统 OpenSSL，也不修改 Debian 的系统库链接。
3. 不允许“找不到铜锁就回退到系统 OpenSSL”的静默行为。缺少指定依赖时，密码模块构建应明确失败。
4. 运行时动态库解析必须验证实际加载路径，避免编译时链接铜锁、运行时却加载系统 OpenSSL 的情况。
5. 初期仅对服务实际使用的密码 API 做最小封装；不在业务模块直接调用 OpenSSL/Tongsuo 专有接口。

## 2. 分阶段落地

### 阶段 A：依赖可识别性

- 编写构建探测程序，输出编译期头文件版本及运行时库版本。
- 验证显式前缀、错误前缀、系统 OpenSSL 前缀三种情形；错误依赖必须失败。
- 在 Debian 13 x86_64 上先完成 8.5.0，再以同样步骤验证 8.4.0。
- 记录 `openssl version -a`、`pkg-config`（若该安装提供对应元数据）、编译器、配置参数和动态链接解析结果。

### 阶段 B：最小 C API 冒烟

依次增加可自动化测试：初始化库、SM2 密钥生成/PEM 写入与读回、SM2/SM3 签名验签（包含篡改负例）。测试私钥仅在临时目录生成，禁止提交。

### 阶段 C：证书功能

再实现 CSR 验证、X.509 v3 证书链、规范要求的 ECDSA-192/SHA-256 与 SM2/SM3 配置、CRL、PEM/DER、PKCS#12。每项均以正向和负向测试覆盖；WAPI 规范字段由后端校验。

### 阶段 D：平台扩展

Debian 13 x86_64 验证通过后，再建立麒麟 V10 ARM64 构建验证；记录工具链、铜锁构建选项、运行时库路径及差异。真实设备/RADIUS 互通另列测试，不以库内测试替代。

## 3. CI 原则

- 当前 Debian 工作流的脚手架测试与 GCC 静态分析保持独立。
- 铜锁源码构建/缓存和密码 API 测试作为单独 job 或明确阶段，固定 tag/commit；不得以浮动分支作为验证基准。
- 8.5.0 与 8.4.0 分开记录结果，避免同一构建目录或缓存混用。
- 在构建依赖和测试程序落地前，不将“CI 通过”描述为铜锁或证书功能已验证。

## 4. 依据

铜锁官方编译说明采用独立安装前缀，并支持分离安装运行库、开发头文件；官方 8.5.0 发布说明列出相对 8.4.0 的功能与安全更新。具体 API、算法参数、证书配置仍须以固定版本的头文件和实际测试结果为准。
