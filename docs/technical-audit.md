# certservers 项目技术尽调与风险评估报告（初步）

- **审查状态：** 初步静态审查
- **审查基准：** `main` 分支，提交 `b86f364e7d46595e6b1d32567fdb817368cf5743`
- **审查范围：** 仓库树、构建入口、服务入口、示例配置、Nginx/systemd 部署文件、架构/安全/证书格式文档、测试与迁移目录说明
- **未执行事项：** 尚未克隆并本地构建；未运行服务；未验证铜锁算法、证书签发、LDAP、RADIUS 或真实设备互通。因此本文不构成运行时或密码学符合性结论。

## 1. 总体判断

当前仓库处于**文档与工程脚手架阶段**，不是可运行的 CA 产品实现。设计文档覆盖了不少关键领域，但文档中的功能描述尚未由实现和测试证明。

首要工作应是建立可构建、可运行、可测试的最小服务骨架，并优先验证密码引擎和证书签发的技术可行性；不建议在核心实现尚不存在时继续大规模扩写功能设计。

## 2. 已由仓库内容直接证实的发现

### P0 — 服务入口尚未实现

`src/main.c` 仅输出“scaffold: implementation pending”并返回 0。没有配置解析、日志、数据库、密码引擎、API 路由或 Unix 域套接字监听实现。

**影响：** 当前程序不会提供设计文档所述的 CA/API 服务。

### P0 — 构建目标仅包含占位入口

`CMakeLists.txt` 只将 `src/main.c` 编译为可执行文件；未发现业务源文件、依赖发现或链接配置。

**影响：** 当前构建无法验证 MariaDB、铜锁、HTTP 服务等技术选型，也没有模块实现可供测试。

### P0 — 部署启动参数与入口不匹配

systemd 单元通过 `ExecStart=/usr/sbin/certservers --config /etc/certservers/certservers.toml` 启动；当前 `main()` 不接收或处理命令行参数。

**影响：** 当前入口不具备读取该配置的能力。需要在服务骨架实现时统一启动参数契约，并增加启动验收测试。

### P1 — 测试目录目前只有说明文档

`tests/unit` 与 `tests/integration` 目前仅有 README 说明，未见测试用例源文件；仓库树中也未见 CI 工作流配置。

**影响：** 目前没有可重复的自动化测试证据或提交级质量门禁。

### P1 — 数据库迁移尚无实际迁移脚本

`sql/migrations` 目前仅有迁移说明，未见初始 schema 或迁移执行器实现。

**影响：** CA、证书、申请、吊销、审计等数据模型尚未通过实际数据库结构验证。

### P1 — 密码引擎仅有计划，未见接入代码

`src/crypto` 目前只有模块说明；构建配置未发现铜锁依赖或链接设置。

**影响：** SM2、SM3、ECDSA、CSR、X.509、CRL、P12 的实际支持状态均未验证。

### P1 — 文档与实现成熟度需要明确区分

架构、安全、LDAP、设备身份和 WAPI 文档描述了目标能力，但当前代码树不能证明这些能力已实现。建议所有项目状态统一标记为“已设计 / 实现中 / 已测试 / 已验证互通”，避免将设计要求误读为现有功能。

## 3. 需要后续核验的高风险事项

以下不是已确认缺陷，而是需要通过代码、构建或实验回答的问题：

1. 铜锁目标版本是否支持项目要求的算法、曲线、OID、X.509/CRL 扩展及 PKCS#12 组合。
2. WAPI 原始标准中的 ASN.1 字段、主体命名、强制域/FLAG、设备类型和扩展如何映射到实现；现有整理文档需逐条对照正式标准复核。
3. CA 私钥调用边界、根/中间 CA 生命周期、密钥备份恢复、签发事务一致性和审计防篡改如何落地。
4. CRL 编号、更新时间、发布、缓存和故障策略能否与目标 RADIUS/TLS 实现正确互通。
5. LDAP 属性映射、组授权、目录故障处理和审批状态转换是否具备服务端强制校验。
6. Nginx、Unix 套接字、systemd 权限与应用层认证授权能否形成完整安全边界。
7. 配置文件中 LDAP URL、StartTLS 和证书校验选项的组合约束是否会被实现正确执行。

## 4. 建议的下一步顺序

### 阶段 A：可构建、可运行的服务骨架
- 实现命令行参数和配置解析；
- 初始化日志和错误处理；
- 创建受权限约束的 Unix 域套接字；
- 明确 HTTP 请求大小、超时、方法和错误响应边界；
- 增加构建与启动测试，修正 systemd 启动契约。

### 阶段 B：密码能力验证，不先做完整 CA
- 固定铜锁版本和构建方式；
- 建立 SM2/SM3、目标 ECDSA 场景的能力探测与测试；
- 验证 CSR 解析/签名、X.509 证书生成/验签、DER/PEM 解析；
- 逐项验证 WAPI 所需字段和扩展；
- 保存测试证书、解析输出和测试环境版本作为证据。

### 阶段 C：数据模型与最小签发闭环
- 定义并评审初始数据库 schema；
- 实现 CA/证书/申请/审计最小数据模型；
- 实现单一测试 CA 的 CSR → 证书签发 → 验证闭环；
- 加入负向测试和数据库事务/文件一致性测试。

### 阶段 D：撤销、LDAP、RADIUS 和端到端互通
按风险逐步实现 CRL、LDAP 审批、RADIUS 集成及目标设备测试；每项都以可复现测试结果作为完成标准。

## 5. 本轮结论

本轮最重要的结论是：**目前的主要风险不是某个已实现模块的细节缺陷，而是设计范围已经显著超前于代码和测试成熟度。**

建议下一轮先完成阶段 A，并同步开展阶段 B 的密码引擎可行性验证。WAPI 规范符合性和目标设备互通应作为独立验证工作，不应由“证书成功生成”替代。
