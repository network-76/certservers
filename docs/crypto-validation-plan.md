# 铜锁与 WAPI 密码能力验证计划

- **状态：** 待执行实验计划，不代表能力已通过验证
- **适用仓库基准：** `main` 分支；当前服务仍为脚手架
- **目的：** 在实现完整 CA 业务前，验证密码库版本、证书配置和 WAPI 关键约束，形成可复现证据

## 1. 当前结论与版本策略

铜锁官方资料列出 SM2、SM3、ECDSA 等算法，以及 TLCP、TLS 1.3 国密能力；官方教程说明不同版本的 SM2 密钥生成 API 有变化。由此不能仅凭算法列表判定项目所需证书配置、扩展、PKCS#12 或终端互通均可用。

**版本策略（当前决策）：**
1. **主测候选：铜锁 8.5.0**。截至本计划更新时，官方 GitHub Releases 页面列出的最新正式版为 8.5.0；8.5.0 是正式版，不使用 pre-release。
2. **稳定维护对照：8.4.x 最新维护补丁版**。官方维护政策明确 8.4.x 至少维护至 2029 年；执行前须核实并记录实际选用的最新补丁 tag，不能默认把 8.4.0 当作最新补丁。
3. 版本固定到明确 tag/commit，不使用浮动的 `latest`。若 8.5.x 后续发布补丁，先评估安全修复和变更，再决定升级并重跑回归。
4. 8.5.0 相较 8.4.0 包含 PQC（后量子密码）算法 ML-KEM、ML-DSA、SLH-DSA，以及 `curveSM2MLKEM768`、`X25519MLKEM768` 等混合密钥协商机制；这构成选择 8.5.x 的前瞻性理由，但不代表本项目当前证书格式或目标设备已经支持 PQC。
5. 不因 TLS/NTLS 功能宣传而推断 WAPI 证书配置或 EAP-TLS 互通已满足。PQC 另列为实验性能力验证，不进入当前签发默认配置。

## 2. WAPI 规则必须进入测试向量

依据仓库所收录的 T/WAPIA 013.5—2024 文本，至少建立以下互斥/组合测试：

### 2.1 算法配置分流
- 符合 GB 15629.11 的无线局域网 WAPI 场景：ECDSA-192 + SHA-256，使用规范指定的算法/曲线 OID。
- TLSec、TISec、WAI 增强协议、AKEA 等列明场景：SM2 + SM3。
- 不允许把所有名为 WAPI 的证书统一套用 SM2 配置；模板必须按协议场景选择算法配置。

### 2.2 强制域与 FLAG
- 兼容型 WAPI 证书可使用强制域 `WAPI`，仅适用于规范指定场景。
- 通用/多协议形式使用 `HUFU` + FLAG 的十进制字符串表示。
- FLAG 的 bit 0 为特殊通用标识：置位时其余位必须为 0；`HUFU1` 表示通用证书。
- 根证书强制域为 `HUFU1`。
- 其他位按规范协议位定义；保留位不得由 UI 任意设置。
- 测试合法单协议、多协议、通用、保留位、bit0 与其他位冲突、超出支持位范围等输入。

### 2.3 证书与 CRL 结构
- 证书必须为 X.509 v3，按 DER 编码；CRL 为 X.509 v2。
- 校验颁发者/主体强制域、国家、管理域、网络域、设备域的规则。
- 校验设备类型与命名格式；测试字段长度、非法字符、缺项和边界。
- 对设备唯一标识扩展（如 MAC OID）验证 OID、ASN.1 类型、唯一性与格式。
- CRL 验证版本、签名算法、颁发者、生效/下次更新时间、撤销序列号/时间/原因及扩展版本约束。
- 以上规则应由后端校验；不能仅依赖前端模板。

## 3. 实验环境与证据要求

每次实验记录：
- 操作系统/版本、架构、编译器版本、铜锁 tag/commit、配置选项；
- 测试命令、退出码、完整工具输出；
- 生成对象的 SHA-256 摘要（测试私钥不得提交仓库）；
- 证书/CRL 的 ASN.1 解析结果、关键字段/OID、验证结果；
- 若涉及互通，记录对端型号/固件、TLS 库/RADIUS 版本、抓包和失败阶段。

测试私钥只用于临时实验，禁止提交到 Git；公开测试证书和非敏感解析输出可作为回归样本。

## 4. 分阶段验证矩阵

| ID | 验证项 | 方法/工具 | 通过条件 |
|---|---|---|---|
| TS-01 | 铜锁版本与构建可复现 | 固定 tag/commit；按官方构建说明编译；记录构建参数 | 干净环境可重复构建，版本信息一致 |
| TS-02 | SM2 密钥生成/读写 | 铜锁命令行与 C API；PEM/DER 读写 | 可生成、解析、重新加载；公钥一致 |
| TS-03 | SM2/SM3 签名验签 | 命令行与 C API，正向/篡改负向测试 | 正确签名通过，篡改数据或签名失败 |
| TS-04 | CSR 验证 | 有效 CSR、错误签名、缺字段、错误算法、畸形 DER | 仅合法且签名有效 CSR 通过 |
| TS-05 | X.509 v3 签发 | 根/中间/叶证书；检查基本约束、Key Usage、EKU、有效期 | 链验证通过；策略字段与预期完全一致 |
| TS-06 | ECDSA-192/SHA-256 WAPI 配置 | 使用规范 OID/曲线生成证书，独立解析 | OID、曲线、公钥用途、签名算法均与规范一致 |
| TS-07 | WAPI 命名及强制域 | 对第 2 节测试向量生成/拒绝证书 | 合法样本精确编码；非法组合被拒绝 |
| TS-08 | CRL v2 | 签发、吊销、生成 CRL、验签、解析 | 版本、签名、时间、序列号和原因正确 |
| TS-09 | PEM/DER/P12 | 导出、重新解析、证书私钥匹配、错误密码 | 内容一致；错误密码失败；无私钥泄漏 |
| TS-10 | 目标互通 | 目标 WAPI 设备、EAP-TLS/RADIUS 环境及抓包 | 按每个目标协议/设备形成独立通过记录 |
| TS-11 | 8.5.0 PQC 算法可用性 | 铜锁命令行/API；分别测试 ML-KEM、ML-DSA、SLH-DSA 的生成、封装/解封装或签名/验签 | API、参数集、正负向结果均记录；不得仅凭算法名称判定通过 |
| TS-12 | TLS 混合 PQC 密钥协商 | 铜锁客户端/服务端配置 `curveSM2MLKEM768`、`X25519MLKEM768`，抓取握手并测试不支持对端的回退/失败行为 | 双端协商结果、协商组、握手失败模式可复现；不支持对端时不静默降级到未批准配置 |
| TS-13 | PQC 与证书/协议边界 | 核对目标协议标准、证书编码、签名算法、客户端/设备及 RADIUS/TLS 组件支持情况 | 明确区分“库内算法可用”“协议可协商”“证书链可验证”“真实设备互通”；未满足条件的场景标记不支持 |

## 5. 建议的首批最小测试样本

1. SM2 根 CA、SM2 中间 CA、SM2 终端证书及有效 CSR。
2. ECDSA-192 WAPI 根/终端证书样本（使用规范指定曲线与 OID）。
3. 一份含设备唯一标识扩展的设备证书。
4. 一份包含多协议 FLAG 的证书、一份 `HUFU1` 通用证书。
5. 一份有效 CRL、一份含至少一个撤销条目的 CRL。
6. 负向样本：无效 CSR 签名、错误 OID、错误 FLAG、过期证书、签名被篡改的 CRL。

## 6. 首轮执行顺序

1. 固定主测 8.5.0 与对照 8.4.x 补丁版本，记录构建环境。
2. 两个版本分别完成 TS-01 至 TS-05，比较基础签发链及 API 差异。
3. 完成 TS-06 至 TS-08，验证 WAPI 特定配置。
4. 完成 TS-09，再进行真实终端/RADIUS 互通 TS-10。
5. 8.5.0 单独执行 TS-11 至 TS-13；PQC 结果不作为当前国密/WAPI 签发通过的替代证据。
6. 将通过/失败的原始输出、版本信息和测试样本索引纳入回归记录。

## 7. 依据与边界

- 铜锁官方发布说明与 Releases 页面：8.5.0 正式版包含上述 PQC 算法及混合密钥协商能力；官方版本维护政策列明 8.4.x 至少维护到 2029 年。执行时应再次核实最新发布与维护政策。
- 官方项目列出的算法和通信协议能力不替代本项目的配置级测试。
- 铜锁官方 SM2 教程指出不同版本的密钥生成 API 存在差异，故需固定版本并验证实际 C API。
- 仓库中的 WAPI 标准文本用于提取测试向量；正式实现前仍应对照用户持有的正式标准原件，特别复核规范性附录、ASN.1 和命名规则。
- 本计划尚未执行。没有真实设备、RADIUS/TLS 环境及原始标准原件时，不宣称互通或完整符合性通过。
