# WAPI 证书格式与签发要求

## 1. 依据与适用范围

本文依据仓库中的《T/WAPIA 013.5—2024 信息安全技术 数字证书管理 第5部分：证书格式》（文件：`docs/wapicert/wapicert.md`）整理平台实现要求。本文区分规范内容、平台设计建议和待互通验证事项；正式实现前应对照规范原文及目标设备要求复核。

## 2. 规范要点

### 2.1 编码与封装

- 三元对等密码安全协议数字证书采用 X.509 v3；CRL（证书吊销列表）采用 X.509 v2。
- 证书和 CRL 使用 DER 编码。
- 存储或传输可采用 PEM/base64 表示；证书、私钥及证书链的组合交付可采用 PKCS#12（常见扩展名 .p12/.pfx）。
- PEM、DER、P12 是编码或封装方式，不代表不同证书类型。

### 2.2 算法不可一概而论

规范按协议场景区分算法，平台不得将所有 WAPI 相关证书统一默认为 SM2：

- 符合 GB 15629.11（所有部分）的 WAPI 产品，采用 ECDSA-192 与 SHA-256 的证书场景，其强制域取值为 `WAPI`。
- TLSec、TISec、WAI 增强协议、AKEA 等规范列举场景采用 SM2/SM3 体系。
- 证书公钥算法、签名算法和曲线参数必须按具体场景、规范 OID 及目标设备兼容性配置。

规范列出的 ECDSA 相关 OID 包括：
- 公钥算法：`1.2.840.10045.2.1`；
- 签名算法：`1.2.156.11235.1.1.1`；
- 曲线参数：`1.2.156.11235.1.1.2.1`。

以上 OID 应作为配置/实现核对项，编码时不得仅依赖字符串拼接。

### 2.3 主体命名与设备类型

证书颁发者和使用者名称涉及强制域、国家、管理域、网络域及设备域等命名元素。规范示例包括国家 `C=CN`、管理域代码，以及以 `CN=设备标识@类型` 表示的设备域。

规范列举的设备类型包括 ASU、AE（例如 AP/AC 等 WAPI 接入设备）、ASUE（WAPI 用户设备）、AAC、REQ、CISU。实际类型、字段顺序、字符串类型、长度及字符限制必须按规范和目标设备要求校验，不能将示例直接当作所有设备的通用规则。

### 2.4 强制域与协议掩码

规范附录 E 定义两种强制域表达方式：

- `WAPI`：用于规范规定的兼容场景；
- `HUFU` + 十进制 FLAG 字符串：通过位掩码表示通用证书或支持的协议组合。

其中 FLAG 的位含义由规范定义；位 0 为通用标识的特殊规则，根证书强制域为 `HUFU1`。平台应以结构化协议选项计算并验证 FLAG，不允许管理员或申请人任意拼接字符串。多用途证书必须验证协议组合合法性，并对目标设备互通进行测试。

### 2.5 扩展与 CRL

规范涉及实体唯一标识、颁发者/使用者密钥标识、密钥用法、CRL 分发点等扩展。规范示例中的设备 MAC 实体唯一标识 OID 为 `1.2.156.11235.3001.1.13.5.1`，其值示例采用 PrintableString；平台应按规范规定的编码和语义实现，不能将任意 MAC 文本未经校验写入扩展。

CRL 应包含规范要求的版本、签名算法、颁发者、生效时间、下次更新时间及撤销条目（序列号、撤销时间、原因）。含扩展的 CRL 应按规范使用相应版本。CRL 签名算法应与 CA 配置和目标验证端兼容。

## 3. 平台设计要求

1. 将 WAPI 证书配置建模为独立证书配置档（profile），至少区分协议场景、算法套件、强制域表达、主体命名规则、设备类型、扩展集合及 CRL 策略。
2. 证书模板引用配置档版本；发布后不可变。申请记录保存配置档和模板版本。
3. Subject、SAN、扩展及算法均由后端依据配置档生成和校验；前端不得直接提交任意 DER/ASN.1 结构或 OID。
4. 对 STA、AP/AC 等不同设备类型使用不同模板；人员身份、设备资产和申请人身份分别建模。
5. 证书签发前验证 CSR 签名、公钥算法/参数、主体字段、用途、有效期和设备/人员授权。
6. 规范示例只用于理解编码，不应直接复制示例序列号、密钥、时间、地址或证书内容到生产环境。
7. 证书与 CRL 均应执行 DER 编码、解析回读和签名验证测试；PEM/P12 仅作为交付封装另行测试。

## 4. 待互通验证清单

- 铜锁版本与所需 ECDSA-192/SHA-256、SM2/SM3 算法及 OID 编码的实际支持情况；
- 不同 WAPI/TLSec/TISec/AKEA 场景的证书链验证和协议协商；
- Subject 字段的字符集、ASN.1 字符串类型、长度、顺序及设备类型标识；
- 强制域 `WAPI` 与 `HUFU+FLAG` 的设备兼容性，尤其多协议位组合；
- 设备唯一标识扩展、Key Usage、CRL Distribution Point 等扩展的互通性；
- CRL 版本、签名、更新时间及终端/RADIUS 吊销检查行为；
- PEM、DER、P12 在目标设备、操作系统和认证客户端上的导入与私钥识别；
- 与目标 RADIUS、TLS 库、supplicant 组合的端到端认证测试。

## 5. 术语与状态标记

- **规范要求**：来自 T/WAPIA 013.5—2024 的条款或附录，实施时以规范原文为准。
- **平台设计**：本项目为实现可配置、可审计和安全校验提出的工程要求。
- **待互通验证**：需在具体密码引擎、RADIUS、终端或设备上实测，不能仅凭证书成功签发判定通过。
