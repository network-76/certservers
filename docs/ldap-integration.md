# LDAP 身份验证与证书申请审核设计

## 1. 建设目标

平台对接标准 LDAP（轻量级目录访问协议）服务器，在证书申请前验证申请人的目录身份，并根据目录属性、申请内容、领域模板和审批策略，决定自动签发、转人工审核或拒绝申请。

LDAP 负责身份目录和凭据验证；本平台负责证书申请策略、审核、签发和生命周期管理。平台不替代 LDAP，也不直接修改 LDAP 中的用户密码或身份资料。

## 2. 兼容范围与连接方式

平台应通过标准 LDAP 协议访问目录服务，并将目录服务器差异封装为适配配置。

- 优先使用 LDAPS（基于 TLS 的 LDAP 连接），或使用 LDAP + StartTLS 将连接升级为加密连接。
- 禁止在未加密的普通 LDAP 连接上发送用户密码。
- 必须验证 LDAP 服务器证书及其信任链，不允许默认关闭证书校验。
- 支持配置多个 LDAP 服务器地址，按策略实现主备或故障切换。
- 支持服务绑定账号（Bind DN）用于搜索用户和读取允许访问的目录属性。
- 用户密码验证应通过 LDAP Bind 完成，不得读取或比较 LDAP 密码哈希，也不得在本平台保存用户 LDAP 密码。
- 支持配置用户搜索基准 DN、用户搜索过滤器、登录名属性、唯一身份属性、用户状态属性及组成员关系属性。
- 通过配置适配常见 LDAP 目录实现；Active Directory 等目录的属性名称和组成员关系规则应作为可配置映射处理，不将某一种目录的字段写死在业务逻辑中。

## 3. 典型申请流程

1. 申请人打开证书申请页面，选择证书领域模板。
2. 申请人输入 LDAP 登录名和密码，或使用已建立的受信任登录会话。
3. 平台通过加密 LDAP 连接搜索用户条目，并验证用户是否存在、是否启用。
4. 平台使用用户 DN 执行 LDAP Bind 验证密码；验证完成后立即释放凭据，不记录密码。
5. 平台读取策略允许的用户属性和组成员关系。
6. 根据领域模板映射规则，将 LDAP 属性填入证书申请表单；字段来源和可编辑性由模板定义。
7. 申请人补充允许填写的字段，提交 CSR 或选择平台生成密钥的受控流程。
8. 平台验证申请内容、CSR 签名、证书用途和领域策略。
9. 策略引擎根据用户组、目录属性、模板、字段差异、风险规则和审批配置，给出自动签发、人工审核或拒绝结果。
10. 自动签发的申请进入签发流程；需审核的申请进入待审批队列；拒绝的申请记录原因并通知申请人。
11. 记录 LDAP 身份标识、属性快照、模板版本、策略版本、申请内容摘要和处理结果，供后续审计。

## 4. LDAP 属性映射

模板应允许管理员将 LDAP 属性映射到证书字段或申请表单字段。例如：

| 证书/申请字段 | LDAP 属性示例 | 说明 |
|---|---|---|
| 用户登录名 | uid、sAMAccountName | 用于登录，不建议作为唯一永久身份标识 |
| 用户唯一标识 | entryUUID、objectGUID | 用于将申请人与目录对象稳定关联 |
| 姓名 | cn、displayName | 可映射到证书主体字段，须按模板规则处理 |
| 姓 | sn | 可用于显示或主体字段 |
| 邮箱 | mail | 可映射到 SAN 邮箱或申请联系信息 |
| 员工编号 | employeeNumber | 可作为内部身份标识或主体字段 |
| 部门 | ou、department | 具体属性因 LDAP 产品而异 |
| 用户组 | memberOf 或组条目关系 | 用于领域访问控制和自动审批策略 |

上述属性仅为常见示例，不保证每个 LDAP 服务器都具有这些属性。管理员必须按实际目录 Schema 配置映射。

必须优先使用目录对象的稳定唯一标识（例如 entryUUID 或 objectGUID）关联用户，不能仅依赖可能被修改或复用的登录名。证书中是否写入某个 LDAP 属性，应由证书模板明确规定，不能默认把全部 LDAP 属性写入证书。

## 5. 自动签发、人工审核与拒绝

平台至少支持三种策略结果：

### 5.1 自动签发
满足全部自动签发条件时，可在申请校验通过后直接签发。例如：
- LDAP 身份验证成功，账号处于启用状态；
- 用户属于允许申请该领域证书的目录组；
- 申请字段来自可信 LDAP 属性或符合模板允许范围；
- CSR 签名有效，算法、密钥长度及证书用途符合策略；
- 申请数量、有效期和重复申请规则通过；
- 不存在需要人工处理的风险标记。

### 5.2 转人工审核
适用于身份已验证，但申请包含例外或需要授权确认的情况，例如：
- 用户申请的证书用途或有效期超出默认范围；
- 用户修改了允许自定义的主体字段或 SAN；
- 申请平台托管私钥并导出 P12；
- 特殊设备、特权用户或敏感业务领域；
- LDAP 属性缺失、组关系不明确或策略要求双人审批。

审核员应能查看 LDAP 身份信息、属性来源、模板规则、申请差异、CSR 摘要和风险原因。审核操作必须记录审核人、时间、意见及审批结果。高风险操作可要求双人审批。

### 5.3 拒绝申请
适用于 LDAP 身份验证失败、账号禁用、无权申请该领域、CSR 无效、申请违反强制策略或命中明确拒绝规则的情况。拒绝原因应使用适当的用户可见提示，避免泄露目录内部结构或敏感策略细节。

## 6. 模板与 LDAP 的协作规则

每个领域模板可以配置：
- 允许申请的 LDAP 用户组或组织范围；
- LDAP 属性到申请字段、证书主体字段和 SAN 的映射；
- 字段来源：系统生成、LDAP 自动获取、用户填写、用户选择；
- 字段约束：必填、选填、只读、允许覆盖、格式校验和枚举选项；
- 默认 CA、证书用途、有效期和密钥算法；
- 是否允许 CSR 模式、平台生成密钥模式及 P12 私钥导出；
- 自动签发条件、人工审核条件和拒绝条件；
- 模板版本及生效时间。

LDAP 自动获取的字段默认应为只读。若业务允许申请人修改，应明确标记为可覆盖字段，并对修改前后的值进行比较、策略检查和审计。用户输入不能覆盖模板中的强制字段或可信身份字段。

## 7. 安全要求

- LDAP 连接凭据存放在受限权限的秘密配置文件或专用密钥管理设施中，不写入仓库示例配置的明文密码。
- 用户 LDAP 密码只用于本次 Bind 验证，不落库、不写日志、不进入审计详情。
- 对 LDAP 登录和申请接口实施速率限制、失败次数控制和异常告警。
- 防止 LDAP 注入：搜索过滤器必须使用正确的 RFC 4515 转义，不能拼接未经转义的用户输入。
- 限制服务绑定账号的目录读取权限，只读取必要属性和组关系。
- 对 LDAP 返回的属性长度、字符集、编码和多值属性进行校验。
- 目录连接超时、不可用、证书验证失败或用户状态无法确认时，不得自动签发；应拒绝或进入明确的待处理状态。
- 申请记录保存必要的身份标识及属性快照，控制个人信息范围和保留期限。
- LDAP 用户身份验证成功不等于申请自动获批，身份验证与证书签发授权必须分开判断。

## 8. LDAP 故障与账号变更

- LDAP 服务不可用时，默认停止新的 LDAP 身份验证和自动签发，不允许把连接失败当作认证成功。
- 对已提交的待审核申请，可保留申请快照并标记目录复核状态；审批时按策略重新核验账号状态和关键组成员关系。
- 用户离职、账号禁用或移出授权组后，应阻止新的申请；已签发证书是否自动吊销应由组织策略决定，并通过明确的同步任务或管理员操作执行。
- 用户登录名变化时，通过稳定唯一标识关联历史申请和证书，避免错误创建新身份。
- LDAP 属性变化不应静默改写已签发证书；如需更新证书，应发起新的申请和签发流程。

## 9. 审计记录

至少记录：
- LDAP 服务器配置标识和认证结果，不记录密码；
- 用户稳定唯一标识、登录名快照和必要的组织信息；
- 领域模板及版本；
- 申请字段的来源、原始值和最终值；
- 自动签发、人工审核或拒绝的策略结果及原因；
- 审核人、审核时间和审批意见；
- 最终证书序列号、签发 CA、有效期和交付格式。

审计日志不得保存用户密码、服务绑定密码、私钥或 P12 导出密码。
