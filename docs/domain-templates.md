# 证书领域模板与字段规则设计

## 1. 设计目标

平台通过“领域模板”描述不同业务场景的证书申请规则。申请人先选择领域，系统根据模板自动填充字段、生成表单、限定可选项，并决定哪些字段可以修改、哪些字段必须由系统或 LDAP 提供。

模板用于减少重复输入和统一证书策略；模板不能代替服务端校验。浏览器提交的任何字段都必须由后端重新按模板版本校验。

## 2. 领域模板示例

初始可预置以下模板，管理员可复制、修改或新建：

| 领域 | 典型对象 | 常见字段和用途 |
|---|---|---|
| Wi-Fi 终端认证 | 员工电脑、手机、平板 | 用户身份标识、客户端认证用途、终端标识 |
| 员工身份认证 | 员工个人 | 员工编号、姓名、部门、邮箱 |
| 网络设备认证 | 交换机、路由器、无线接入点 | 设备名称、设备编号、管理地址 |
| 服务器身份认证 | 内部服务器和服务 | DNS 名称、IP 地址、服务器认证用途 |
| 自定义领域 | 特殊业务对象 | 管理员定义的字段、映射和约束 |

模板名称只是业务分类，实际证书内容由字段映射、证书扩展和签发策略共同决定。

## 3. 字段来源与编辑规则

每个字段都应配置来源类型和编辑策略：

| 字段来源 | 含义 | 示例 |
|---|---|---|
| 系统生成 | 由平台生成，用户不可修改 | 证书序列号、签发时间 |
| LDAP 自动获取 | 从已验证的目录用户条目读取 | 姓名、邮箱、员工编号、部门 |
| 用户填写 | 由申请人输入 | 设备 DNS 名称、用途说明 |
| 用户选择 | 从管理员配置的枚举选项选择 | 证书有效期档位、设备类型 |
| 管理员锁定 | 由模板或管理员指定，申请人不可修改 | CA、强制 EKU、最长有效期 |

每个字段还应配置：
- 是否必填；
- 是否允许覆盖自动填充值；
- 是否只读；
- 默认值和可选值；
- 格式、长度、字符集及取值范围；
- 是否写入证书，以及映射到 X.509 的哪个字段或扩展；
- 修改后是否触发人工审核。

## 4. X.509 字段与业务字段分离

模板需要区分“申请表单字段”和“最终证书字段”。例如：
- 表单中的员工姓名可以映射到 Subject 的 CN，也可以只作为申请记录信息。
- 员工编号可映射到 Subject 的 OU 或自定义策略约定字段，但应评估隐私和互通性。
- DNS 名称、IP 地址应按 SAN 对应类型写入，不能简单拼进 CN。
- 客户端认证和服务器认证的 EKU、Key Usage 应由模板强制约束。
- 证书序列号、签发者、有效期和签名算法由 CA 签发过程控制，不允许申请人直接指定。

不要把所有 LDAP 属性默认写入证书。只写入业务明确需要、经过授权且适合公开给证书使用方的字段。

## 5. 模板版本与审批

- 模板发布后生成不可变版本号；修改已发布模板时创建新版本。
- 每份申请记录必须保存模板 ID 和版本号。
- 申请提交后，审批和签发应使用该申请绑定的模板版本，避免管理员修改模板导致历史申请规则变化。
- 模板可设置默认审批方式：自动签发、人工审核或按规则决定。
- 对字段覆盖、敏感用途、平台生成私钥、P12 导出等情况可强制转人工审核。
- 模板停用后禁止新申请；已有申请按明确的迁移或完成策略处理。

## 6. 服务端校验

服务端必须执行：
- 字段白名单、类型、长度、字符集和格式校验；
- SAN 类型及值的规范化与校验；
- Subject 字段的长度及编码检查；
- Key Usage、EKU、算法、有效期和 CA 选择的策略校验；
- LDAP 字段来源和用户组授权检查；
- 禁止用户通过篡改请求绕过只读字段、强制值和审批要求；
- 将用户提交值与模板默认值、LDAP 值进行差异比较，并将重要差异写入审计。

## 7. 推荐管理界面

管理员在“证书管理 → 领域模板”中创建模板：
1. 基本信息：模板名称、领域标识、说明、启停状态。
2. 申请对象：允许的 LDAP 用户组或组织范围。
3. 字段定义：字段名称、来源、默认值、是否必填、是否可编辑。
4. 证书规则：Subject、SAN、Key Usage、EKU、算法、有效期、CA。
5. 密钥交付：CSR 模式、平台生成密钥模式、PEM/P12 格式及私钥导出权限。
6. 审批规则：自动签发条件、人工审核条件、拒绝条件。
7. 发布管理：版本号、生效时间和变更说明。

申请人只看到当前领域模板允许其填写或选择的字段，不显示内部策略表达式、LDAP 服务凭据或不必要的目录信息。
