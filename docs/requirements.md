# 项目需求说明

## 1. 项目目的

建设一套可私有化部署的数字证书颁发与管理服务，用于 RADIUS、Wi-Fi 802.1X 和 EAP-TLS 网络终端身份认证场景，重点支持 SM2 国密算法体系。

## 2. 功能需求

### 2.1 CA 管理
- 支持 CA（证书颁发机构）基础信息管理。
- 规划根 CA 与中间 CA 的层级结构。
- 支持 CA 证书导入、查看、有效期管理和状态管理。
- 根 CA 私钥应支持离线保管，不要求在线业务进程持有根私钥。

### 2.2 证书申请与签发
- 支持 X.509 v3 数字证书。
- 支持 SM2 公钥及 SM2-with-SM3 签名算法。
- 接收并验证 PKCS#10 CSR（证书签名请求）。CSR 应包含申请者公钥、主体信息，并由申请者对请求内容签名；CA 必须验证签名。
- 支持证书模板、主体字段、主题备用名称（SAN）、密钥用途和扩展密钥用途策略。
- 支持证书签发、查询、下载和导出。
- **必须支持 PEM 和 P12（PKCS#12）两种交付格式。** PEM 支持证书、证书链和密钥材料的独立文件或按约定组合导出；P12 支持将证书、可选私钥及证书链封装为一个受密码保护的文件。文件格式是交付方式，不改变证书本身的 X.509 内容。

### 2.3 密钥生成与 P12 导出规则
- 默认采用终端本地生成密钥并提交 CSR 的方式；此模式下终端私钥不上传 CA 平台，平台不能导出包含该私钥的 P12 文件。
- 为满足需要 P12 安装包的终端场景，可提供可选的“平台生成终端密钥”流程：平台生成密钥对、签发证书，再将证书、私钥和必要证书链封装为 P12。
- 平台生成的终端私钥只能在经过授权的导出流程中短暂使用；必须设置独立导出密码，避免写入日志、数据库明文或长期临时文件，并在导出完成后清理内存及临时数据。
- 对平台生成密钥的场景，应明确告知管理员：私钥曾由 CA 平台生成或处理。高安全场景优先采用终端本地生成密钥，或由受信任的终端管理系统完成密钥注入。
- P12 导出应支持设置友好名称、证书链内容和加密保护参数；必须验证导出文件可被目标操作系统或认证客户端导入。
- PEM 导出应明确文件内容及命名，例如证书文件、证书链文件和（如允许导出）私钥文件；私钥默认不得与公开证书混放到无保护目录。

### 2.4 证书生命周期
- 支持证书吊销及吊销原因记录。
- 支持 CRL（证书吊销列表）的生成、签名、发布和更新。
- OCSP（在线证书状态协议）作为后续阶段评估功能，不作为第一阶段交付前提。
- 记录证书序列号、签发者、有效期、状态和关联申请信息。

### 2.5 管理与审计
- 提供 Web 管理界面和版本化 API。
- 支持管理员身份认证、角色权限控制和会话管理。
- 对签发、吊销、CA 操作、配置变更和登录等安全事件进行审计。
- 对私钥生成、私钥导出、P12 创建、下载及失败事件单独审计；记录操作者、证书标识、时间和结果，不记录导出密码或私钥内容。

## 3. 非功能需求
- 后端采用 C 语言，数据库采用 MariaDB。
- Nginx 提供 HTTPS 接入，并通过 Unix 域套接字访问 C 业务服务。
- C 业务服务不开放公网 TCP 监听。
- 使用 CMake 构建，使用 systemd 管理服务。
- 实施输入校验、权限检查、审计、密钥保护、备份与恢复机制。

## 4. 互通性验收要求

签发 SM2 X.509 证书不等于具备国密 TLS 或 EAP-TLS 兼容能力。必须在目标环境中验证完整认证链路，包括终端操作系统及 supplicant（802.1X 认证客户端）、RADIUS 服务端及其 EAP-TLS 实现、TLS 库或密码提供程序、证书链、用途、密码套件协商，以及吊销检查行为。

PEM 与 P12 均须进行目标终端导入测试。尤其要验证 SM2 证书及私钥的 P12 封装是否被目标系统、移动设备和认证客户端正确识别；不能只以常规 RSA 证书测试结果代替国密测试。

## 5. RADIUS 协作需求

CA 应提供稳定的 CRL 发布地址，并记录 CRL 编号、生成时间和下次更新时间。RADIUS 应能够定期获取并校验 CRL。若未来实现 OCSP 或证书状态 API，必须定义身份认证、访问控制、超时、缓存和故障时的处理策略。
