# 设备身份与设备组管理设计

## 1. 目标与边界

本设计用于管理无线接入点（AP）、无线控制器（AC）、交换机、路由器及其他网络设备的证书身份。设备身份与人员身份分开建模：LDAP 用户及用户组用于人员身份验证和人员证书授权；设备证书由平台设备资产、设备组及设备申请策略授权。

不得为了给 AP 等设备授权而在 LDAP 中创建“假用户”。设备证书的 Subject、SAN、设备类型和设备唯一标识应来自设备资产或经审核的设备申请信息。

## 2. 身份对象

平台至少区分以下对象：

- **人员身份**：来自 LDAP 的真实用户目录对象，以 entryUUID、objectGUID 等稳定标识关联。
- **设备资产**：由管理员导入、同步或登记的实体设备，具有平台内部资产 ID、设备类型、厂商/型号、序列号、MAC 地址等属性。
- **设备组**：按站点、用途、设备类型或管理责任划分的设备集合，用于授权和模板适用范围。
- **证书申请人**：发起申请的人员或管理员，与证书最终主体可以不同。
- **证书主体**：证书所代表的人员、设备或服务身份。

申请人代设备申请时，必须分别记录申请人和目标设备；申请人的 LDAP 组成员关系不能自动赋予任意设备的证书申请权限。

## 3. 设备登记与授权

设备可通过以下方式登记：

1. 管理员手工创建或批量导入资产；
2. 从可信资产管理系统同步；
3. 设备持有预置凭据或已有证书，完成受控注册；
4. 经人工审核的申请创建待确认资产。

每台设备应具有不可变的平台资产 ID。MAC 地址、主机名、IP 地址和序列号可能变更或重复，不能单独作为唯一授权依据。设备标识冲突、重复登记或身份无法验证时，应转人工处理。

设备组支持创建、编辑、成员维护、启停及授权策略配置。设备组的成员变更、授权变更和设备移组操作必须审计。

## 4. 设备证书申请流程

1. 申请人登录平台；人员申请人通过 LDAP 验证，管理员通过平台管理身份验证。
2. 申请人选择“设备证书”领域，并选择有权申请的设备资产。
3. 平台验证申请人是否具有该设备或设备组的申请权限。
4. 系统按设备类型加载对应模板，自动填充可信资产字段。
5. 设备本地生成密钥并提交 CSR 为优先方式；无法本地生成密钥的设备可采用经批准的密钥注入或平台生成方式。
6. 平台校验 CSR 签名、算法、主体字段、设备资产关联、模板版本和申请策略。
7. 根据策略自动签发、转人工审核或拒绝。
8. 签发后将证书序列号、有效期、设备资产 ID、模板版本和交付状态关联保存。

设备证书更新应验证设备与原资产/证书的关联；不能仅凭可复制的 MAC 地址或设备名称自动续期。

## 5. WAPI 设备类型与模板

针对 WAPI 场景，模板应区分终端设备与接入基础设施设备。设备类型标识应按适用规范和实际互通要求配置，不应把所有设备统一映射为同一种主体类型。

至少规划：

- **WAPI STA 终端模板**：用于无线终端（如电脑、手机等），可关联人员身份或终端资产；人员与终端关联关系应由组织策略决定。
- **WAPI AP/AC 设备模板**：用于无线接入点、无线控制器等网络设备，关联设备资产和设备组，不要求对应 LDAP 人员账号。
- **其他网络设备模板**：按设备类型、协议用途和厂商互通要求独立配置。

具体 Subject 命名、强制域、协议标识、算法及扩展必须依据适用的 WAPI 证书格式规范和目标设备要求配置，详见《WAPI 证书格式与签发要求》。

## 6. 权限模型

权限至少按以下维度组合判断：

- 操作者角色：申请人、设备管理员、证书审核员、CA 管理员；
- 目标设备或设备组的管理范围；
- 设备类型与证书领域；
- 可申请的证书用途、有效期和密钥交付方式；
- 是否允许代申请、自动签发或必须人工审批。

设备组授权只限定申请范围，不替代 CSR、证书字段、密钥算法和签发策略的强制校验。高风险设备或平台生成私钥应可配置双人审批。

## 7. 生命周期与审计

设备停用、报废、丢失、转移或退出管理范围时，应阻止新申请，并按组织策略吊销关联证书。设备组移除不应静默改变已签发证书；是否吊销需由明确规则触发。

审计至少记录设备资产 ID、设备组、申请人、目标设备、模板及版本、CSR 摘要、审核人、签发证书序列号、吊销原因和操作结果。不得记录私钥或 P12 密码。

## 8. 待确认事项

- 各类设备的可信注册方式及设备持有凭据；
- 设备资产系统的同步接口和冲突处理规则；
- AP/AC/STA 的准确证书主体字段与规范版本；
- 目标厂商对证书算法、扩展、P12/PEM 导入方式的要求；
- 设备离线、失联或退役时的吊销时限及在线踢除联动策略。
