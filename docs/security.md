# 安全设计

## 1. CA 私钥保护
- 根 CA（证书颁发机构）私钥应离线保存，在线业务服务不应直接持有根私钥。
- 中间 CA 私钥必须加密保存；条件允许时优先通过 HSM（硬件安全模块）、SDF 或 SKF 等密码设备完成密钥操作。
- 严禁将明文私钥写入 MariaDB、日志、临时文件或普通备份。
- 私钥解密口令、设备 PIN 和其他密钥材料不得硬编码在源代码或示例配置中。

## 2. 文件与进程权限
- 对配置文件、证书文件、私钥文件和运行目录设置最小必要权限。
- C 服务使用独立系统账户和用户组运行。
- Unix 域套接字建议权限为 `0660`，父目录不得对无关用户开放写权限。
- 不得因为请求来自本机套接字就默认信任调用者；仍须执行应用层身份认证和授权。

## 3. PEM 与 PKCS#12 导出安全
- PEM（文本封装格式）导出时，默认将证书、证书链与私钥分开处理；私钥仅在用户明确选择且有权限时导出。
- PKCS#12（个人信息交换语法标准，常见扩展名 .p12/.pfx）文件可能同时包含终端证书、对应私钥和证书链，必须设置导出密码。
- P12 导出密码不得写入日志、数据库、审计详情或 URL；通过独立、安全的交互方式交付给用户。
- 生成的 P12 临时文件应使用受限权限，避免写入公共临时目录；下载完成或任务过期后应安全清理。
- 对私钥导出操作实施单独权限、二次确认和完整审计。可配置禁止私钥导出，仅允许导出证书和链。
- CSR（证书签名请求）模式下，私钥通常由终端自行生成并保留，CA 平台只收到 CSR，因此平台不能凭 CSR 还原或导出该私钥，也就不能生成包含该私钥的 P12。若要由平台生成带私钥的 P12，必须另行设计受控的密钥生成、密钥托管和安全交付流程。

## 4. Web 与 API 安全
- 管理入口使用 HTTPS，并配置安全的 TLS 参数。
- 实施角色访问控制、会话保护、CSRF（跨站请求伪造）防护、速率限制和严格输入校验。
- API 应验证调用者身份和操作权限，对敏感操作要求二次确认或更强认证。
- 日志不得记录私钥、密码、令牌或完整的敏感请求内容。
- 管理页面 HTTPS 证书与终端身份认证 CA 分开管理。

## 5. RADIUS 与 CA 通信安全
- CRL 通过 HTTPS 发布；RADIUS 下载时必须验证 CRL 的数字签名、颁发者、有效期和编号，不能仅凭 HTTPS 下载成功就认定内容可信。
- RADIUS 应缓存最近一次验证通过的 CRL，并明确规定 CRL 过期、下载失败和缓存缺失时的处理策略。
- OCSP 或状态 API 如投入使用，应采用 HTTPS；跨系统接口优先使用 mTLS（双向 TLS 认证）或强身份凭据，并实施最小权限、访问审计和速率限制。
- 不向 RADIUS 暴露 MariaDB 账号，不允许 RADIUS 直接读写 CA 数据库。
- 证书状态查询故障时，应依据明确的 fail-open（故障开放）或 fail-closed（故障关闭）策略处理。

## 6. 备份与恢复
- 数据库元数据、证书文件和 CA 私钥分别制定备份策略。
- CA 私钥备份必须加密并实施严格的双人控制或离线保管流程。
- 定期演练恢复流程，验证证书链、数据库关联关系和 CRL 发布能力。

## 7. 吊销与应急响应
- 定义证书吊销审批、原因记录和操作审计。
- 定义 CRL 生成、发布、更新周期和过期告警。
- 建立 CA 私钥泄露、CA 证书失陷、错误签发和 CRL 发布异常的应急流程。
- 所有时间相关校验依赖可靠的系统时钟，并监控时间同步状态。


## 8. LDAP 身份验证与目录安全

- LDAP 连接必须使用 LDAPS 或 LDAP + StartTLS；验证 LDAP 服务器证书和信任链，不得默认关闭证书验证。
- 用户密码仅用于 LDAP Bind 验证，不读取密码哈希，不写入数据库、日志、审计记录或临时文件。
- 服务绑定账号遵循最小权限，只允许搜索用户和读取业务所需属性。
- LDAP 搜索过滤器必须按 RFC 4515 规则转义用户输入，防止 LDAP 注入；不得直接拼接未经转义的登录名或搜索条件。
- 限制 LDAP 连接超时、搜索结果数量、属性数量和属性长度；对登录失败实施速率限制和告警。
- LDAP 不可用、服务端证书验证失败或用户状态无法确认时，默认停止自动签发；不得将目录连接失败视为认证成功。
- 优先使用 entryUUID、objectGUID 等稳定目录对象标识关联用户；登录名仅作为显示和登录属性。
- 只保存证书申请所必需的 LDAP 属性快照，并配置个人信息访问权限和保留期限。
- LDAP 身份验证与证书签发授权必须分离。用户认证成功后，仍须检查领域资格、用户组、模板规则和审批策略。
- 用户离职、账号禁用或组成员关系变化后，应阻止新的申请；已签发证书的吊销策略由组织明确制定。

## 9. 领域模板与审批安全

- 模板发布后使用不可变版本；每份申请绑定提交时的模板版本，防止审批过程中规则被静默修改。
- 浏览器只负责展示字段和提交数据，所有字段来源、可编辑性、取值范围和证书扩展必须由后端再次校验。
- LDAP 自动获取字段默认只读；允许覆盖时必须显式配置，并记录原值、修改值和修改人。
- 证书用途、Key Usage、EKU、算法、有效期上限、CA 选择和私钥交付权限应由管理员策略控制，不能由申请人任意放宽。
- 自动签发条件应可审计；敏感领域、字段例外、平台生成私钥和含私钥 P12 导出可强制人工审批。
- 审批人不得审批自己提交的申请；高风险业务可要求双人审批。
- LDAP 认证通过不等于申请获批，必须独立执行证书申请资格和审批决策。
